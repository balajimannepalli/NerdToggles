# Nerd Toggles — Locked product specification

## Product
Native, offline Android 15+ Quick Settings tile utility optimized for vivo V27 5G (V2246). Name: **Nerd Toggles**. App ID: `com.nerdtoggles.app`. Initial personal APK; design for later Play Store review. No ads, analytics, trackers, network calls, INTERNET permission, backend, root, Shizuku, wireless debugging, continuous ADB connection, shell bridge, Accessibility abuse, persistent foreground service or battery optimization exemption. USB ADB is permitted only for one-time grants and manual *read-only diagnostics*. No promises of broad OEM compatibility.

## Stack and size
Kotlin + Jetpack Compose with minimal Material 3; minSdk 35 (Android 15), compileSdk/targetSdk latest stable supported by environment after validation. One app module, Gradle Kotlin DSL. Keep source layout shallow. No Room, Hilt/Koin, Navigation Compose, Firebase, Retrofit, WorkManager or large icon libraries. Use `SharedPreferences` for small local user configuration. No Android backup/restore for app preferences; uninstall removes app data, **but cannot automatically undo changes made to system settings**. A lean, accessible visual style: Material You colors where practical, system light/dark, short copy, compact rows, simple icons, no decorative animations. APK size **aspirational** target 5–8 MB; measure actual size and installed footprint rather than promising it.

## App UI
Three lightweight destinations: Controls, Setup, Device (one Activity; simple state navigation). Controls show each item with its actual state, support status, and Add Tile action if functional. Feature detail/config from long press or tapping an item; no fake switches. Setup shows `WRITE_SECURE_SETTINGS` grant status, `Settings.System.canWrite()` and steps for special access, exact one-time Windows ADB command for the actual applicationId, and permission recheck. Device shows model, SDK, firmware/build and clear capability statuses. Unsupported experimental network feature visible but explicitly labeled; no active toggle tile that claims unsupported functionality. Support Android official `requestAddTileService()` where applicable and manual fallback; Android owns placement/order. The app must not claim it can silently add/remove/reorder tiles.

## V1 feature behavior
1. **Private DNS**: tap cycles Off -> Automatic -> Custom -> Off. Read the **existing device Private DNS mode/hostname** using Settings APIs and preserve configured hostname when cycling. `private_dns_mode` values may be `off`, `opportunistic`, `hostname`; use `private_dns_specifier` for configured hostname when appropriate. Never erase an existing hostname merely to turn DNS off. Custom state without a valid hostname opens configuration/chooser and does not claim a state transition. Offer optional Cloudflare `one.one.one.one`, Google `dns.google`, AdGuard `dns.adguard-dns.com` plus manual input; default to **no preselected provider**. Clearly explain provider differences without exaggerated privacy claims. Verify write and report failures honestly; DNS actual resolution/connectivity cannot be guaranteed by readback alone.
2. **Screen timeout**: tap cycles user-configurable **nonempty, distinct, ordered** durations; provide reasonable initial selections such as 15s/30s/1m/2m/5m, but all editable via UI. Read `Settings.System.SCREEN_OFF_TIMEOUT` (milliseconds); write only after `Settings.System.canWrite()` and applicable authorization. If current device value is outside configured list, use a documented deterministic next-state rule; do not silently discard custom settings. Respect OEM enforcement and verify readback.
3. **Animation scale**: ONE tile changes all three settings together (`window_animation_scale`, `transition_animation_scale`, `animator_duration_scale`). Default cycle 0x -> 0.5x -> 1x; config may expose supported cycle choices. Read all three independent values. If values differ, show Mixed and choose a deterministic next target; avoid claiming all equal until verified. When a partial write fails, report partial state; optional best-effort restore of snapshot, not misleading success. ADB-grantable settings access is needed; test Vivo behavior.
4. **Developer Options**: read `Settings.Global.DEVELOPMENT_SETTINGS_ENABLED`; attempt settings API only after appropriate permission. Verify and report. Disabling master switch may affect debugging/other settings; show warning before first potentially disruptive action or require an opt-in setting. Do not assume toggling it also toggles USB debugging. Never force an activity or enable USB debugging behind user's back.
5. **4G/5G**: visible EXPERIMENTAL read-only/status/Settings shortcut; **no purported direct switch in V1**. Settings.Global `preferred_network_mode*` is not an authoritative modem-command API; a Settings.Global write alone is NOT proof of changing the radio. The modern telephony setter `TelephonyManager.setAllowedNetworkTypesForReason` requires privileged `MODIFY_PHONE_STATE`/carrier privileges. No root, Shizuku, hidden binder, reflection bypass, persistent ADB or radio-restart workaround. Do not request `MODIFY_PHONE_STATE`. If read state unavailable to regular app, show Unknown, not incorrect 4G/5G. Preferred 5G and presently connected to 4G can coexist. Only offer explicitly labeled system Settings fallback when supported; otherwise explain manual navigation.

## Tile lifecycle / trust
Implement independent TileService per supported feature; shared stateless controller helpers, lazy access, minimal allocations; no always-on service. On listening, read live state. On tap, re-read -> apply -> verify -> update tile; handle SecurityException, failure, process recreation, permission revocation, device lock where applicable. Tile `STATE_UNAVAILABLE` for missing required permission or unsupported operation. Long press routes through `TileService.ACTION_QS_TILE_PREFERENCES` via manifest-declared Activity intent filter; do not rely on capturing a TileService long-click event. Tile state refresh when app changes settings, plus on listening; no polling daemon. `BIND_QUICK_SETTINGS_TILE` belongs on `<service android:permission=...>`, not requested as a runtime permission. Avoid exposing sensitive state on lock screen.

## Quality / release
Only mark a feature Supported after verified on actual Vivo hardware; distinguish Code implemented, Permission needed, Untested, Supported, Unsupported. Include unit tests for pure cycle/reconciliation/validation functions and manual device test checklists. No secret logs (do not log DNS hostname). No personal identifiers or raw diagnostic dumps in source or APK. Target latest stable Play requirements when publishing, separately review `WRITE_SECURE_SETTINGS` policy; Play publication is not guaranteed. No background/remote collection.

## Implementation workflow
Follow each phase prompt in order. Each phase must compile or document tooling blocker, test relevant behavior, and stop for review; do not pre-build all features. Do not introduce dependencies without justifying APK impact. Never assert hardware behavior from settings readback alone.
